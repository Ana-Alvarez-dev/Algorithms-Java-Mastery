# State Space Trees

## Algorithms Java Mastery

A **State Space Tree** is the fundamental mathematical model used to represent the search process performed by a Backtracking algorithm. Rather than viewing recursion as a sequence of function calls, a state-space tree represents every possible decision as a branch and every partial solution as a node.

Each path from the root of the tree to one of its leaves corresponds to a sequence of decisions made by the algorithm. Some paths eventually produce valid solutions, while others violate one or more constraints and are abandoned through **backtracking**.

The state-space tree is not an implementation detail but an abstract representation of the search space. It allows algorithm designers to reason about recursive exploration, pruning, branching, and computational complexity independently of any programming language.

Understanding state-space trees is essential for analyzing why Backtracking algorithms work and why their worst-case complexity is often exponential.

# 1. Purpose

The purpose of this document is to:

- define a state-space tree;
- explain its role in Backtracking;
- understand how recursive decisions are represented;
- identify nodes, branches, and leaves;
- prepare for pruning and complexity analysis.

---

# 2. Definition

A **State Space Tree** is a rooted tree that represents every possible state generated while solving a problem.

Conceptually:

```text
Initial State
        ↓
Possible Decisions
        ↓
New States
        ↓
Complete Solutions
```

Each node represents one possible state of the problem.

---

# 3. Why State Space Trees Are Needed

Backtracking algorithms repeatedly make decisions.

Instead of viewing these decisions independently:

```text
Decision 1

Decision 2

Decision 3
```

they are organized into a search tree.

```text
Root
        ↓
Decision
        ↓
Decision
        ↓
Decision
```

This representation simplifies reasoning about recursive exploration.

---

# 4. Root Node

The **root** represents the initial state before any decision has been made.

Conceptually:

```text
Start

↓

Empty Solution
```

Every search begins from this node.

---

# 5. Internal Nodes

Internal nodes represent **partial solutions**.

Example:

```text
Root

↓

A

↓

A B
```

The solution is incomplete, but still valid.

The algorithm continues exploring from these nodes.

---

# 6. Leaf Nodes

Leaf nodes represent states where recursion stops.

There are two possible cases.

## Complete Solution

```text
Complete Assignment

↓

Valid Solution
```

---

## Dead End

```text
Constraint Violated

↓

Backtrack
```

Both terminate the current recursive path.

---

# 7. Branches

Each branch represents one possible decision.

Conceptually:

```text
Current State

↓

Choose Candidate
```

Different branches correspond to different choices.

---

# 8. Paths

A path from the root to any node represents the sequence of decisions taken so far.

Example:

```text
Root

↓

A

↓

A C

↓

A C D
```

This path corresponds to one partial solution.

---

# 9. Search Space

The complete tree represents the **search space**.

Conceptually:

```text
All Possible
Decisions

↓

All Possible
Solutions
```

Backtracking explores this space systematically.

---

# 10. State Expansion

Each recursive call expands the current node.

```text
Current State

↓

Candidate 1

Candidate 2

Candidate 3
```

Every candidate creates a new branch.

---

# 11. Recursive Exploration

Backtracking performs a depth-first traversal of the state-space tree.

Conceptually:

```text
Choose

↓

Explore

↓

Continue

↓

Backtrack

↓

Next Choice
```

Only one branch is explored at a time.

---

# 12. Dead Ends

Some branches cannot produce valid solutions.

Example:

```text
Partial Solution

↓

Constraint Violated

↓

Stop
```

These branches are abandoned immediately.

---

# 13. Valid States

A valid state satisfies every constraint considered so far.

Conceptually:

```text
Current Solution

↓

All Constraints Satisfied
```

Only valid states continue expanding.

---

# 14. Invalid States

An invalid state violates at least one constraint.

Example:

```text
Current Solution

↓

Constraint Violated

↓

Backtrack
```

Exploring descendants of an invalid node is unnecessary.

---

# 15. Tree Depth

The depth of the tree corresponds to the number of decisions made.

Example:

```text
Root

↓

Level 1

↓

Level 2

↓

Level 3
```

The deepest level generally represents complete candidate solutions.

---

# 16. Branching Factor

The **branching factor** is the number of children generated by each node.

Conceptually:

```text
One State

↓

3 Choices
```

Higher branching factors generally produce larger search spaces.

---

# 17. Example: Permutations

Suppose the elements are:

```text
A

B

C
```

The initial state-space tree begins as:

```text
            {}
         /   |   \
        A    B    C
```

Each branch represents the first selected element.

The remaining levels generate every possible ordering.

---

# 18. Example: N-Queens

Each tree level represents one row of the chessboard.

Conceptually:

```text
Row 1

↓

Column Choice

↓

Row 2

↓

Column Choice
```

Branches violating attack constraints are pruned immediately.

---

# 19. Relationship with Pruning

Pruning reduces the size of the state-space tree.

Without pruning:

```text
Explore
Everything
```

With pruning:

```text
Invalid Node

↓

Stop
```

The algorithm avoids exploring entire subtrees.

---

# 20. Relationship with Complexity

The size of the state-space tree determines the computational complexity.

Larger trees require:

- more recursive calls;
- more memory;
- more execution time.

Pruning attempts to reduce the effective size of the explored tree.

---

# 21. Java Perspective

In Java, a state-space tree is rarely created explicitly.

Instead, it exists **implicitly** through recursive method calls.

Each recursive invocation represents:

- one node;
- one partial solution;
- one level of the tree.

The call stack naturally stores the current path.

# 24. Key Takeaways

After completing this document, the learner should understand that:

- a state-space tree represents every possible state explored by a Backtracking algorithm;
- the root corresponds to the initial problem state;
- internal nodes represent partial solutions;
- leaf nodes correspond to complete solutions or dead ends;
- branches represent candidate decisions;
- Backtracking performs a depth-first traversal of the state-space tree;
- pruning eliminates invalid branches before they are fully explored;
- the size of the state-space tree largely determines the computational complexity of Backtracking algorithms;
- recursive Java implementations implicitly traverse the state-space tree through the call stack.
